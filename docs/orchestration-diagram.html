Technical Deep Dive

Inside the AI Orchestrator

How Lane coordinates agents, manages sessions, and preserves context behind the scenes. This is what happens when you run a command.

📋

Agent Registry

Catalog of all 10 agents with capabilities, MCP services, and handoff paths.

  • Stores agent definitions (name, phase, capabilities)
  • Maps agents to workflow types
  • Defines input/output contracts
  • Specifies MCP service access
  • Triggers: /agent, workflow start
💾

Session Handler

Persists workflow state to .ai-session/current.yaml across interactions.

  • Creates session ID and timestamps
  • Tracks current phase/agent
  • Records workflow progress
  • Logs all decisions made
  • Stores handoff history
🧠

Orchestrator

Central coordinator that analyzes tasks, routes workflows, activates agents, and manages transitions.

  • Analyzes task → selects workflow type
  • Determines starting phase and agent
  • Activates agents with context injection
  • Validates phase outputs
  • Triggers automatic handoffs
  • Coordinates MCP service access
🔄

Context Manager

Preserves and transfers context between agents across handoffs.

  • Initializes session context
  • Loads relevant context per agent
  • Saves agent outputs and decisions
  • Filters context by relevance level
  • Archives completed sessions
⌨️

Slash Commands

User interface that triggers orchestrator actions via /work-ticket, /agent, /handoff.

  • /work-ticket → Workflow Router
  • /agent [name] → Agent Activator
  • /handoff → Handoff Protocol
  • /progress → Session Reader
  • /phase [n] → Phase Jump
🤝

Handoff Protocol

Formal transition procedure between agents with validation and context transfer.

  • Validates completion criteria
  • Generates handoff summary
  • Transfers context to next agent
  • Updates session state
  • Supports rollback if rejected

What Happens Behind the Scenes

1. Command Parsing

When you type /work-ticket "add feature", the command is parsed and the task description is passed to the Orchestrator's Workflow Router for analysis.

2. Workflow Selection

The Orchestrator analyzes trigger words (fix→Quick, create→BMAD, system→Enterprise) and selects the workflow type, then queries the Agent Registry for the agent sequence.

3. Context Injection

Before activating each agent, the Context Manager loads relevant history: previous decisions, phase outputs, constraints, and formats it into the agent's prompt.

4. Automatic Handoff

When an agent completes, the Handoff Protocol validates outputs, generates a summary, updates the session state, and immediately activates the next agent—no user action needed.
