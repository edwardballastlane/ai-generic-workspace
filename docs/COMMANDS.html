ENGINEER COMMANDS

🎯 Workflow Commands

Start and manage development workflows.

/work-ticket "task" Smart router - AI analyzes your task and picks the right workflow (Quick, Full BMAD, or Enterprise) Workflow
/jira-epic PPT-123 Analyze Jira epic, build dependency graph, and create branch chain for ordered task execution Workflow
/jira-epic [PRD text] Parse PRD document, break into tasks with dependencies, generate epic context files Workflow
/analyze "task" Start in Analysis phase (Analyst, Product Owner) - for research-heavy tasks Phase
/plan "task" Start in Planning phase (Architect, Designer) - skip analysis, go straight to design Phase
/implement "task" Start in Implementation phase (Developer, Tester) - for tasks where you know the design Phase
/deliver "task" Start in Delivery phase (Deployer, Documenter) - for deployment and docs only Phase

💡 Which one to use?

/work-ticket is the default - it auto-detects the right workflow. Use /jira-epic for multi-task epics with dependencies. Use phase commands only when you want to skip earlier phases.

🛠 Spec-to-Implementation Pipeline

Go from idea to running code through a structured pipeline with parallel agent execution.

/spec "task" Generate a structured PRD (Product Requirements Document) from a task description Pipeline
/breakdown <spec-file> Create a wave-based implementation plan from a spec - groups tasks into parallelizable waves Pipeline
/swarm-implement <plan> Execute an implementation plan with parallel agent teams working across waves Pipeline

Example Flow

# 1. Generate a spec
/spec "Add role-based access control"

# 2. Break it into waves of parallel tasks
/breakdown docs/specs/rbac-spec.md

# 3. Execute with agent swarm
/swarm-implement docs/plans/rbac-plan.md

💡 Structured Artifacts

Each stage produces structured artifacts (spec files, plan files) so you can review and adjust before moving to the next step.

📋 Epic & PRD Management

Manage complex multi-task work with dependency tracking and branch chains.

/jira-epic PPT-123 Fetch Jira epic, analyze child issues, infer dependencies, create branch chain Jira Mode
/jira-epic [PRD text] Parse PRD document into discrete tasks with layer-based dependencies PRD Mode
/jira-epic docs/feature.md Read PRD from file and break into tasks PRD Mode
/work-ticket --epic PPT-123 Resume work on next ready task from an epic Resume

Branch Chain Model

Each task's PR targets its blocker's branch, creating a chain:

# Epic: PROJ-100 (User Authentication)
PROJ-1234 (no blockers) → PR to: dev
PROJ-1235 (blocked by 1234) → PR to: PROJ-1234
PROJ-1236 (blocked by 1235) → PR to: PROJ-1235

Layer-Based Dependencies

Tasks are automatically organized by layer when no explicit Jira links exist:

Layer 1 - Schema

Database, models, migrations, types

Layer 2 - Service

Core services, integrations, modules

Layer 3 - Logic

Business logic, handlers, processing

Layer 4 - API

Endpoints, controllers, routes

Layer 5 - UI

Components, screens, views

Layer 6-8

Testing, documentation, deployment

# Epic context (small, just dependencies)

# Individual task files (full Jira details)

💡 Resuming Epic Work

In a new conversation, just run /work-ticket --epic PPT-123. The agent reads the context files and picks up where you left off - no need to re-fetch from Jira!

📁 Project Management

Add projects to the workspace - supports local paths, GitHub URLs, or creating new projects.

/add-project ~/code/my-app Add existing local project (creates symlink automatically) Project
/add-project https://github.com/user/repo Clone from GitHub Project
/add-project my-new-app Create new empty project Project

Examples

# Add existing project (symlinked, git platform auto-detected)
./scripts/add-project ~/code/my-react-app
./scripts/add-project /path/to/project custom-name

# Clone from GitHub (auto-detects: github)
./scripts/add-project https://github.com/user/repo
./scripts/add-project git@github.com:user/repo.git

# Clone from Bitbucket (auto-detects: bitbucket + workspace)
./scripts/add-project https://bitbucket.org/mycompany/repo

# Clone from GitLab
./scripts/add-project https://gitlab.com/user/repo

# Create new project
./scripts/add-project my-new-app

# Verify
./scripts/list-projects

💡 Per-Project Git Platform

Git platform is auto-detected from the remote URL and saved to .ai-contexts/<project>.yaml. Different projects can use different platforms - work on Bitbucket in the morning, GitHub in the afternoon!

🔗 Auto-Symlink

Local paths are automatically symlinked - your original files stay in place and changes sync both ways. Use --copy flag if you need a separate copy instead.

🔧 Workspace Scripts

Shell scripts the AI uses for state management and context caching.

Project Discovery

Script Command Purpose
list-projects ./scripts/list-projects Discover available projects (AI runs this first)
add-project ./scripts/add-project <path-or-url> Create new project folder

Context Caching (Token Savings)

Script Command Purpose
generate-context ./scripts/generate-context <project> Cache project analysis in .ai-context.yaml
validate-context ./scripts/validate-context <project> Check if cached context is still valid

Session Management

Script Command Purpose
start-session ./scripts/start-session <workflow> "<task>" [project] Initialize workflow session state
update-session ./scripts/update-session <action> [args] Update session during workflow

Session Update Actions

# Move to next agent in sequence
./scripts/update-session next-agent

# Mark agent as completed
./scripts/update-session complete-agent "architect"

# Track output files
./scripts/update-session add-output "src/components/Button.tsx"

# View current state
./scripts/update-session show
